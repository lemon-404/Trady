# API 공통 응답 규격

## 1. 응답 원칙

- 응답 본문은 JSON 형식을 사용한다.
- `code`는 문자열로 반환한다.
- 성공 응답에는 `data`, 오류 응답에는 `errors`를 포함한다.
- 반환 데이터가 없으면 `data`는 `null`로 반환한다.
- `errors`는 배열로 반환하며, 필드를 특정할 수 없으면 `field`는 `null`로 반환한다.
- 템플릿의 `...`은 추가 항목을 의미하며 실제 응답에는 포함하지 않는다.

## 2. 응답 코드

| 코드 범위 | 분류 | 의미 |
|---|---|---|
| `0` | 성공 | 요청 처리 성공 |
| `1xxx` | 요청 오류 | 잘못된 요청값, 필수값 누락, 형식 불일치 |
| `2xxx` | 인증·인가 오류 | 인증 실패, 접근 권한 없음 |
| `3xxx` | 리소스·상태 오류 | 데이터 없음, 중복, 현재 상태에서 처리 불가 |
| `9xxx` | 서버 오류 | 서버 내부 오류, 시스템 장애 |

| code | 의미 | HTTP Status |
|---|---|---|
| `0` | 요청 처리 성공 | 200 OK |
| `1000` | 잘못된 요청값 | 400 Bad Request |
| `1001` | 필수 입력값 누락 | 400 Bad Request |
| `1002` | 입력값 형식 불일치 | 400 Bad Request |
| `2000` | 인증 실패 | 401 Unauthorized |
| `2001` | 접근 권한 없음 | 403 Forbidden |
| `3000` | 데이터가 존재하지 않음 | 404 Not Found |
| `3001` | 중복된 데이터 | 409 Conflict |
| `3002` | 현재 상태에서 처리 불가 | 409 Conflict |
| `9000` | 서버 내부 오류 | 500 Internal Server Error |

## 3. 성공 응답 템플릿

```jsonc
{
  "code": "0",
  "message": "{{성공 메시지}}",
  "data": {
    "{{필드명}}": "{{값}}",
    ...
  }
}
```

## 4. 오류 응답 템플릿

```jsonc
{
  "code": "400",
  "message": "{{오류 메시지}}",
  "errors": [
    {
      "field": "{{오류 필드명 또는 null}}",
      "message": "{{필드 오류 메시지}}"
    },
    ...
  ]
}
```
