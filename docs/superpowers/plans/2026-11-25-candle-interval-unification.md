# 봉 단위 표준화 구현 계획

## 목적과 승인 범위

API·DB의 봉 단위를 `1m`, `5m`, `15m`, `30m`, `60m`, `1d`, `1w`, `1M`, `1y`로 통일한다.
사용자가 승인한 공통 enum·키움 매핑·기존 데이터 변환 설계를 구현한다.
실제 사용자 DB에 SQL을 실행하지 않는다. 조회 페이지 크기와 실시간 갱신 주기는 유지한다.

## 구현 순서

1. 표준 분봉 코드로 저장한 데이터가 현재 조회에서 누락되는 것을 계약 테스트로 재현한다.
2. 공통 CandleInterval과 JPA 변환기를 추가한다. 엔티티·저장·Repository는 enum을 사용한다.
3. 키움 TR 및 tic_scope 매핑을 한곳으로 모으고 과거 수집과 실시간 수집에서 함께 사용한다.
4. 실시간 Scope에는 공통 봉 단위 및 기존 갱신 주기만 남기고 조회의 문자열 변환을 제거한다.
5. 관련 테스트를 enum 계약에 맞추고 실제 저장값·외부 요청값·조회 연결을 검증한다.
6. 사전 점검 SQL과 트랜잭션 기반 변환 SQL을 준비한다. 충돌한 OHLCV는 자동 선택하지 않는다.
7. 관련 테스트와 코드 리뷰 후 결과·제약을 기록한다.

## 검증 기준

- 9개 표준 코드가 대소문자를 구분하고 이전 분봉 표기를 신규 저장에 허용하지 않는다.
- JPA 저장값은 enum 이름이 아닌 표준 코드이며 다시 읽을 때 enum으로 복원된다.
- 키움 분봉 요청의 tic_scope는 숫자 문자열이며 API·DB에는 숫자 문자열이 남지 않는다.
- 과거·실시간 수집이 같은 봉 단위로 저장하고 동일 시각 재수집 시 중복되지 않는다.
- 조회 응답·페이지네이션·오류 계약과 기존 갱신 및 호출 제한 동작을 유지한다.
- DB 변환은 동일 OHLCV 중복만 병합하고 값이 충돌하거나 미지원 표기가 있으면 중단한다.

## 배포 조건

수집·조회 애플리케이션을 중지하고 데이터 사전 점검 및 변환을 완료한 다음 새 코드를 기동한다.
enum 변환기는 이전 숫자 표기를 허용하지 않는다. 미변환 DB에서 새 코드만 먼저 실행하지 않는다.

## 완료 기록

- 공통 enum·JPA 변환기·키움 매핑·과거/실시간 수집·조회 및 관련 테스트를 변경했다.
- 표준 코드로 저장한 분봉의 조회 누락 12건을 먼저 재현한 후 조회·저장 타입을 통일했다.
- 전체 main/test Java 소스를 Java 17 대상으로 컴파일했다.
- 관련 JUnit 테스트 142개 성공, 실제 DB·외부 API 실행 조건이 없는 수동 테스트 3개 건너뜀.
- Gradle은 기존 플러그인 캐시를 해석하지 못하여 로컬 라이브러리와 JUnit Launcher로 검증했다.
  Hibernate는 build.gradle에 지정된 7.4.15.Final 버전을 사용했다.
- H2 2.4.240에서 IN CHECK가 닫힌 생성 세션을 참조하는 오류를 독립 JDBC 코드로 재현했다.
  테스트에 한정된 CandleDataJpaTest 설정으로 물리 연결을 유지했다. 운영 코드의 제약은 유지한다.
- 읽기 전용 코드 리뷰 및 git diff --check 통과.
- 기존 DB 점검·변환 SQL과 절차는 backend/docs/migrations/candle-interval/에 준비했다.
  PostgreSQL SQL의 실제 실행은 하지 않았다. 운영 데이터 충돌 해소 및 변환은 적용 전에 남아 있다.
