## 1. 결제 시점 단순화

실제 주식 거래에서는 체결 이후 정해진 결제일에 결제가 이루어지지만, 본 프로젝트에서는 실제 시간의 경과를 재현하는 것을 목적으로 하지 않는다.

따라서 체결일로부터 실제 2일이 경과할 때까지 대기하지 않고, D+2 결제 대상 데이터를 생성한 후 결제 배치를 즉시 실행할 수 있도록 구현한다.

결제 예정 데이터에는 체결일과 결제 예정일(D+2)을 구분하여 관리하되, 테스트 및 개발 환경에서는 결제 기준일을 조정하거나 결제 배치를 직접 실행하여 D+2 결제 시점에 도달한 상황을 즉시 구성한다.

이를 통해 실제 시간의 경과와 관계없이 다음과 같은 D+2 결제의 핵심 처리 과정을 검증한다.

- 결제 예정 데이터 생성 및 상태 관리
- 대량 결제 데이터의 배치 처리
- 결제 결과의 계좌 반영
- 배치 처리 중 장애 및 실패 처리
- 실패 데이터 재처리
- 동일 결제의 중복 처리 방지
- 배치 재실행 시 멱등성 및 데이터 정합성 유지

즉, **D+2라는 업무상의 결제 시점은 데이터로 유지하되 실제 2일의 대기 시간은 생략하고, 결제 처리 과정에서 발생할 수 있는 배치·장애·재처리·정합성 문제를 경험하는 데 초점을 둔다.**

## 2. 데이터 정합성 보장 원칙

주문 → 체결 → 결제 → 계좌 반영의 각 처리 단계는 자신의 책임 범위에서 필요한 데이터 정합성을 보장한 후 다음 단계로 전달한다.

다음 단계에서는 이전 단계의 처리 결과가 정상적으로 보장되었다고 신뢰하며, 매 처리마다 전체 거래 데이터를 다시 조회하여 정합성을 검증하지 않는다. 이를 통해 불필요한 조회 및 처리 비용이 거래 과정에 추가되는 것을 방지한다.

**전체 거래 과정의 정합성은 통합 테스트에서 주문·체결·결제·계좌 데이터를 종합적으로 비교하여 검증한다.**

```text
주문
 ↓
단계별 정합성 보장
 ↓
체결
 ↓
단계별 정합성 보장
 ↓
D+2 결제
 ↓
단계별 정합성 보장
 ↓
계좌

───────────────

통합 테스트
 ↓
주문 / 체결 / 결제 / 계좌
전체 데이터 정합성 검증
```
