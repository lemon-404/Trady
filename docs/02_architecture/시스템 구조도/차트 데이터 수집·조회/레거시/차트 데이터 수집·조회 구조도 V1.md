## 차트 데이터 적재와 조회 책임을 분리한 이유

차트 조회 요청 시 외부 API 호출 여부를 판단하도록 구성하면 DB 조회, 데이터 존재 여부 판단, 외부 API 호출 및 저장까지 조회 기능이 담당하게 되어 책임이 복잡해진다.

예를 들어 다음과 같은 과정을 거쳐야 한다.

Client 요청  
→ DB 조회  
→ 데이터 존재 여부 판단  
→ Kiwoom REST API 요청  
→ 응답 데이터 변환·검증  
→ Client 응답 / DB 저장  

따라서 다음과 같이 책임을 분리한다.

- **데이터 적재**: Kiwoom REST API에서 OHLCV 데이터를 수집·검증하여 DB에 저장
- **차트 조회**: DB에 저장된 OHLCV 데이터만 조회하여 반환

이를 통해 데이터 수집과 조회 로직의 결합을 줄이고, 차트 조회 성능 측정 및 최적화에 집중할 수 있도록 한다.

이는 대규모 OHLCV 데이터의 조회 성능을 측정·개선한다는 차트 기능의 목적과도 맞는다.

그러므로 동일한 DB 데이터와 조회 조건으로 성능을 측정할 수 있으므로, 키움 API의 응답 시간이나 호출 제한이 조회 성능 측정 결과에 섞이지 않는다.
