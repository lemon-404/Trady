**기능 ID:** ODR-001  
**기능명:** 지정가 매수  
**우선순위:** 상 

### 사전 조건

작성 목적: 기능 수행 전에 충족되어야 하는 상태
예시:
- 사용자가 로그인한 상태여야 한다.
- 사용자가 모의투자 계좌를 보유하고 있어야 한다.

### 기능 요구사항

작성 목적: 입력에 따라 시스템이 수행해야 하는 특정 동작, 기능, 서비스
예시: 시스템이 수행해야 하는 동작
- 사용자는 종목, 주문 수량, 지정 가격을 입력할 수 있어야 한다.
- 지정가 이하의 매도 호가가 존재하면 체결할 수 있어야 한다.
- 미체결 수량은 주문 내역에 유지되어야 한다.

### 비기능 요구사항

작성 목적: 성능, 보안, 가용성, 유지보수성 등 시스템의 품질 속성 및 제약 조건
예시:
- 동시에 여러 주문이 발생해도 주문 가능 금액이 초과 사용되지 않아야 한다.
- 주문 처리 중 장애가 발생해도 데이터 정합성이 유지되어야 한다.


### 엣지 케이스

예시:
- **주문 취소와 체결이 동시에 발생한다면?**  
  → 먼저 확정된 처리 결과를 기준으로 주문 상태를 결정하고, 체결된 수량은 취소되지 않도록 처리

- **주문 가능 금액과 주문 금액이 정확히 일치한다면?**  
  → 수수료 등 추가 비용까지 충족하면 정상적으로 주문 접수

- **100주를 주문했지만 30주만 체결된다면?**  
  → 30주는 체결 처리하고 나머지 70주는 미체결 상태로 유지

- **동일한 주문 요청이 동시에 두 번 전달된다면?**  
  → 동일한 요청 식별자를 가진 재전송이라면 주문을 한 번만 생성하고 기존 주문 결과 반환



### 예외 처리

예시:
- **주문 가능 금액이 부족하다면?**  
  → 주문 거부 + 잔고 부족 메시지

- **존재하지 않는 종목이라면?**  
  → 주문 거부 + 종목 정보 확인 안내

- **네트워크가 끊긴다면?**  
  → 주문 처리 상태 확인 + 재시도 안내

- **외부 시세 API에 장애가 발생한다면?**  
  → 주문 처리 제한 + 일시적인 장애 안내


### API URL
`POST /api/orders`

### Request
```json
{
  "stockCode": "005930",
  "orderType": "LIMIT",
  "side": "BUY",
  "quantity": 10,
  "price": 70000
}
```

### Response

**201 Created**
```json
{
  "orderId": 123,
  "stockCode": "005930",
  "orderType": "LIMIT",
  "side": "BUY",
  "quantity": 10,
  "price": 70000,
  "status": "PENDING"
}
```

**400 Bad Request**
```json
{
  "code": "INVALID_ORDER_QUANTITY",
  "message": "주문 수량은 1 이상이어야 합니다."
}
```

**409 Conflict**
```json
{
  "code": "INSUFFICIENT_BALANCE",
  "message": "주문 가능 금액이 부족합니다."
}
```
