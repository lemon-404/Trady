
# Trady 추진 성과 및 기대효과 v1

## 1. 문서 목적

본 문서는 <u>네 가지 핵심 기능에 대해 취업용 개인 프로젝트에서 경험하고 검증할 기술적 범위의 상한을 정의한다.</u>

<u>실제 증권사 수준의 대규모 시스템 구현을 목표로 하지 않으며,</u> <mark>개인 개발 환경에서 직접 문제를 재현하고 원인을 분석하며 개선 전후 결과를 측정할 수 있는 수준</mark>까지 진행한다.

본 문서에서 정의한 범위를 기준으로 프로젝트를 진행하며, <mark>핵심 기술 경험과 직접적인 관련이 없는 추가 기능이나 과도한 시스템 확장은 진행하지 않는다.</mark>

---

## 2. 주식 차트 조회

### 2.1 목표

- 대규모 OHLCV 시계열 데이터 저장 및 조회
- 데이터 증가에 따른 조회 성능 저하 경험
- 데이터베이스 병목 분석
- 조회 구조 개선
- 개선 전후 성능 비교

### 2.2 데이터 규모

- 15분봉 OHLCV
- 약 1,000개 종목
- 최대 약 1억 건
- 데이터 규모 단계적 증가

예시

- 100만 건
- 1,000만 건
- 5,000만 건
- 1억 건

### 2.3 성능 검증

- 종목 + 기간 조건 조회
- 데이터 규모별 응답시간 측정
- P95 / P99 측정
- DB 실행 계획 확인
- 병목 지점 확인
- 개선 전후 동일 조건 재측정

### 2.4 개선 범위

문제가 발생하는 경우 필요한 방법만 단계적으로 검토한다.

- 쿼리 최적화
- 인덱스
- 복합 인덱스
- 파티셔닝
- 캐시

### 2.5 최종 도달 범위

- 약 1억 건 규모 데이터 저장
- 대규모 데이터에서 특정 종목·기간 조회
- 병목 발생 구간 확인
- 병목 원인 분석
- 필요한 조회 구조 개선
- 개선 전후 성능 수치 비교

## 3. 주식 주문·체결

### 3.1 목표

- 동시 주문 처리
- Race Condition 재현
- 계좌 데이터 정합성 유지
- 주문 중복 처리 방지
- 동시성 제어에 따른 성능 변화 측정
- 주문 처리량의 단계적 확대

### 3.2 주요 검증 상황

- 동일 계좌 동시 매수
- 동일 계좌 동시 매도
- 주문가능금액 초과 주문
- 보유수량 초과 주문
- 동일 주문 중복 요청
- 요청 실패 후 재시도
- 다수 사용자 동시 주문

### 3.3 정합성 검증

- 주문가능금액 음수 발생 여부
- 보유수량 음수 발생 여부
- 중복 체결 여부
- 중복 계좌 반영 여부
- 주문과 계좌 상태 일치 여부

### 3.4 개선 범위

문제가 발생하는 경우 필요한 방법을 비교·적용한다.

- Transaction
- DB Lock
- Optimistic Lock
- Pessimistic Lock
- Atomic Update
- Idempotency
- 트랜잭션 범위 조정

필요한 경우 각 방식의 정합성과 성능 차이를 비교한다.

### 3.5 성능 검증

- 동시 사용자 단계적 증가
- 동시 주문 수 단계적 증가
- TPS 측정
- P95 / P99 측정
- 오류율 측정
- Lock 경합 확인
- DB Connection 병목 확인
- 데이터 정합성 확인

### 3.6 최종 도달 범위

- 동시 주문 Race Condition 재현
- 동시성 제어 적용
- 정합성 오류 0건 검증
- 동시 주문 규모 단계적 확대
- 처리 한계 확인
- 병목 분석
- 개선 전후 TPS / 응답시간 비교
- 정합성과 성능 사이 Trade-off 확인

## 6. 계좌 현황

### 6.1 목표

- 주문·체결·결제 결과의 일관된 계좌 반영
- 여러 거래 과정에서 계좌 정합성 유지

### 6.2 검증 데이터

- 현금
- 주문가능금액
- 보유종목
- 보유수량
- 평균매입가
- 평가금액
- 평가손익
- 총자산
- D+1 결제 예정 금액
- D+2 결제 예정 금액

### 6.3 주요 검증 상황

- 매수 주문 이후 계좌
- 매도 주문 이후 계좌
- 부분 체결 이후 계좌
- 다수 주문 동시 처리 이후 계좌
- D+2 결제 이후 계좌
- 실패 및 재처리 이후 계좌

### 6.4 최종 도달 범위

```text
주문
↓
체결
↓
결제 예정 데이터 생성
↓
D+2 결제
↓
계좌 반영
```

전체 과정에서 다음을 검증한다.

- 주문 상태 일치
- 체결 상태 일치
- 보유수량 일치
- 주문가능금액 일치
- 결제 예정 금액 일치
- 결제 완료 금액 일치
- 최종 계좌 자산 일치

## 8. 프로젝트 종료 기준

다음 항목을 완료하면 프로젝트의 핵심 기술 목표를 달성한 것으로 판단한다.

### 8.1 차트 조회

- 1억 건 수준 데이터 구축
- 데이터 규모별 조회 성능 측정
- 병목 분석
- 최소 1회 이상의 구조 개선
- 개선 전후 결과 비교

### 8.2 주문·체결

- 동시 주문 문제 재현
- 데이터 정합성 확보
- 동시 주문 규모 확대
- 처리 한계 측정
- 최소 1회 이상의 구조 개선
- 개선 전후 결과 비교

### 8.3 주문 매칭

- 기본 호가창
- 가격·시간 우선
- 부분 체결
- 주문 상태 관리
- 기본 성능 및 정합성 검증

### 8.4 D+2 결제

- 대량 배치 처리
- 장애 상황 재현
- Retry / 재처리
- 중복 결제 방지
- 재실행 이후 데이터 정합성 검증

### 8.5 계좌

- 주문 → 체결 → 결제 → 계좌 전체 흐름 연결
- 동시 주문 이후 정합성 검증
- 장애 및 재처리 이후 최종 계좌 정합성 검증

위 범위를 완료한 이후 추가적인 대규모 트래픽 처리, 분산 시스템 구축, 고급 투자 기능 등의 구현은 본 프로젝트의 필수 범위에 포함하지 않는다.
