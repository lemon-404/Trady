# 봉 단위 표준화와 기존 데이터 변환

API·DB는 `1m`, `5m`, `15m`, `30m`, `60m`, `1d`, `1w`, `1M`, `1y`를 사용한다.
`CandleInterval`이 공통 정의이고, 엔티티·저장 서비스·Repository에서는 문자열 대신 enum을 전달한다.
JPA 변환기는 enum 이름이 아닌 표준 코드를 저장한다. 이전 숫자 표기는 신규 코드에서 허용하지 않는다.

키움의 TR와 숫자 `tic_scope`는 `KiwoomCandleMapping`에서 변환한다.
과거 수집과 실시간 수집이 이 매핑을 함께 사용한다. 일·주·월·년봉 요청에는 `tic_scope`를 보내지 않는다.
`RealtimeCandleScope`는 공통 봉 단위와 갱신 주기만 연결한다.

## 실행 순서

이 SQL들은 자동 실행되지 않으며, 코드 변경 과정에서 실제 DB에 실행하지 않았다.

1. 기존 DB 백업을 준비한다. 수집기·스케줄러를 포함한 이전 애플리케이션을 모두 중지한다.
2. [01-preflight.sql](01-preflight.sql)을 실행한다. 미지원 값과 OHLCV 충돌 여부를 확인한다.
3. 충돌한 행은 원본을 확인하여 유지할 값을 결정한다. 변환 SQL은 충돌 시 예외를 발생시키고 전체 작업을 취소한다.
4. [02-normalize.sql](02-normalize.sql)을 전체 실행한다. psql에서는 `-v ON_ERROR_STOP=1`을 사용한다.
5. 사전 점검 SQL을 다시 실행하여 숫자 분봉·미지원 값·중복이 남지 않았는지 확인한다.
6. 새 애플리케이션을 시작한다. 조회 및 재수집 후 동일 종목·봉 단위·시각에 새 중복이 생기지 않는지 확인한다.

변환 SQL은 테이블을 잠그고 충돌을 먼저 확인한다. 동일 OHLCV 중복은 표준 코드 행을 유지하고 숫자 코드 행만 삭제한다.
나머지 숫자 코드는 표준 코드로 바꾼다. 값 제한 CHECK 제약을 추가하여 숫자 코드 재유입을 방지한다.
변환이 커밋된 후 이전 코드로 되돌리려면 데이터·제약도 함께 복원해야 한다. 두 표기 중복이 병합되므로 단순 역치환은 원상 복구가 아니다.
